# Contributing

Start with the [README](README.md) and [RFC #1](rfcs/0001-minimum-viable-school-board-campaign-os.md). This is a concept/RFC repository, not the production application. No elaborate contributor process is needed.

## Useful first contributions

- Open an [Issue](https://github.com/GuyWhoKnowsTheGuy/political-coop/issues) about a candidate problem, missing constraint, or concrete improvement.
- Use [Discussions](https://github.com/GuyWhoKnowsTheGuy/political-coop/discussions) for exploratory questions.
- Challenge assumptions, including architecture, subscription economics, and succession design. Disagreement is welcome; explain the tradeoff.
- Recommend an existing open-source project, with its license, maintenance status, and likely integration costs.
- Identify a legal/compliance question and the workflow or jurisdiction it affects. Do not present an unresolved question as settled advice.
- Submit a small documentation pull request or propose an RFC describing the problem, alternatives, tradeoffs, and unanswered questions.

For RFC #1, a short response with the candidate problem, smallest useful workflow, evidence, and what to leave out is enough. No special template is required.

## Keep the scope clear

Do not build the production application or copy the demo's source into this repository. Code contributions will become useful as implementation scope is agreed. Distinguish proposed behavior from capabilities that actually exist.

Keep discussions technical and respectful. Party advocacy is not a substitute for product evidence. Never post credentials, private campaign/contact data, or personal information in public issues or examples.

This repository uses [GPLv3](LICENSE). Submit only material you have the right to contribute, and preserve attribution and third-party license notices. Project software defaults to GPLv3; any practical exception should be discussed and documented.
